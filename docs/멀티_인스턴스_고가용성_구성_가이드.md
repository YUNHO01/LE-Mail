# 🌐 LEMail 멀티 인스턴스 및 고가용성(HA) 구성 가이드

본 문서는 LEMail 메일 플랫폼을 대규모(1,000명 ~ 10,000명 이상) 운영 환경에서 무중단 서비스를 제공하기 위해 **이중화, 수평 확장(Scale-Out), 로드밸런싱 및 분산 공유 스토리지**를 구축하는 엔지니어링 가이드입니다.

## 2. 계층별 멀티 인스턴스 상세 구성

### 2.1 로드 밸런서 (HAProxy / L4) 구성
LEMail은 **HTTP(웹메일, API)**, **SMTP(수신/발송)**, **IMAP(메일박스 조회/동기화)**의 서로 다른 통신 특성을 가집니다.

```haproxy
# /etc/haproxy/haproxy.cfg 예시

global
    maxconn 100000
    log /dev/log local0

defaults
    log global
    mode tcp
    timeout connect 5000ms
    timeout client  300000ms    # IMAP IDLE 장기 세션 고려
    timeout server  300000ms

# 1. 웹메일 프론트엔드 (HTTP/HTTPS)
frontend fe_web
    mode http
    bind *:80
    bind *:443 ssl crt /etc/ssl/certs/lemail-combined.pem
    redirect scheme https if !{ ssl_fc }
    default_backend be_web

backend be_web
    mode http
    balance roundrobin
    cookie SRVNAME insert indirect nocache
    server web01 10.0.1.11:9000 check cookie web01
    server web02 10.0.1.12:9000 check cookie web02

# 2. REST API & Inbound ESMTP (포트 2525)
frontend fe_smtp_inbound
    bind *:25
    mode tcp
    default_backend be_smtp_inbound

backend be_smtp_inbound
    mode tcp
    balance roundrobin
    server api01 10.0.1.11:2525 check
    server api02 10.0.1.12:2525 check

# 3. IMAP / IMAPS (포트 143, 993)
# 중요: 클라이언트당 연결 세션 유지를 위해 source IP Hash 방식 적용
frontend fe_imaps
    bind *:993
    mode tcp
    default_backend be_imaps

backend be_imaps
    mode tcp
    balance source
    server imap01 10.0.1.21:1993 check
    server imap02 10.0.1.22:1993 check
```

### 2.2 분산 공유 스토리지 (NFS v4 / EFS / CephFS)
다중 API 서버와 다중 IMAP 서버가 동일한 메일 원문(`.eml`) 및 첨부파일을 조회해야 하므로 고성능 분산 스토리지가 필수적입니다.

#### 마운트 경로 구조
```text
/shared/lemail/
├── mail-spool/        # 비차단 인바운드 수신 스풀
├── mail-archive/      # 영구 보존 원본 EML (YYYY-MM/ 하위)
├── mail-attachments/  # 분할 해시 첨부파일
└── license/           # 정품 라이선스 파일 (lemail-license.lic)
```

#### 최적화된 NFS v4 클라이언트 마운트 옵션 (`/etc/fstab`)
```ini
10.0.2.100:/lemail_data  /shared/lemail  nfs4  rw,noatime,nodiratime,rsize=1048576,wsize=1048576,hard,intr,timeo=600,retrans=2,_netdev  0  0
```
- `noatime, nodiratime`: 수많은 EML 읽기 작업 시 파일 접근 시각 갱신 I/O를 원천 제거하여 성능 30% 이상 향상.
- `rsize, wsize=1048576`: 1MB 단위 대용량 블록 입출력 지원.

### 2.3 데이터베이스 고가용성 (MySQL HA)

#### 권장 이중화 방안
1. **클라우드 환경**: AWS RDS for MySQL (Multi-AZ + Aurora Read Replica) 또는 GCP Cloud SQL HA.
2. **온프레미스/베어메탈 환경**:
   - **Primary-Replica + Orchestrator/MHA**: Primary(Write 전용) + 1~2개 Replica(Read 전용 및 Failover).
   - **MySQL Group Replication (InnoDB Cluster)**: 3노드 액티브-패시브 쿼럼 클러스터 구축.

#### DB 연결 풀 분산 전략
각 노드의 `apps/api` 및 `services/imap`은 환경변수를 통해 연결 풀을 관리합니다:
```bash
# .env 설정
DB_HOST=10.0.3.10          # VIP (또는 AWS RDS Endpoint)
DB_PORT=3306
DB_POOL_SIZE=30            # 노드당 풀 크기 (총 노드 수 * 30 < MySQL max_connections)
```

### 2.4 Redis 고가용성 (Sentinel / Cluster)
LEMail은 **BullMQ 큐**와 **IMAP IDLE 실시간 푸시(Pub/Sub)**, **사서함 캐시**를 Redis에 의존합니다.

- **Redis Sentinel (3노드 구성)**:
  - 1 Primary + 2 Replicas + 3 Sentinels
  - Primary 장애 시 1~3초 이내에 Replica를 새 Primary로 자동 승격(Failover).
- **IMAP IDLE 실시간 Pub/Sub 분산**:
  - A 서버의 ESMTP가 메일을 수신하여 DB에 저장하면, Redis 채널 `imap:event:{userId}`로 브로드캐스트.
  - B 서버에 접속 중인 사용자의 IMAP 데몬이 즉시 이벤트를 수신하여 클라이언트 소켓에 `* 4 EXISTS` 알림을 밀어줍니다.

### 2.5 멀티 인스턴스 환경의 라이선스 동기화 정책
- 라이선스 파일(`lemail-license.lic`)은 **공유 스토리지(`/shared/lemail/license/lemail-license.lic`)**에 위치합니다.
- 관리자가 웹 콘솔을 통해 신규 라이선스를 업로드하면:
  1) 공유 스토리지의 라이선스 파일이 자동 갱신됩니다.
  2) MySQL `system_licenses` 테이블에 신규 서명과 파일 해시가 기록됩니다.
  3) 모든 노드(API 1/2, IMAP 1/2, Haraka 1/2)는 30초 이내에 동일한 공유 파일과 DB 정보를 확인하여 **중단 없이 라이선스가 전사 인스턴스에 일괄 반영**됩니다.
